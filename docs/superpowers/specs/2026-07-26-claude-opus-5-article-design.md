## 主メッセージ

Claude Opus 5は、2026年7月24日に公開されたOpus 4.8の後継モデルである。100万トークンのコンテキスト、最大128kトークンの出力、入力$5・出力$25／100万トークンという基本条件はOpus 4.8と同じだが、深い推論、長時間のエージェント作業、コーディング、追加の推論計算を成果へ結び付ける能力が強化された。

「Fable 5に近い性能を半額で得られる」という公式の位置付けをそのまま結論にはしない。公式ベンチマークに加え、Artificial Analysisの第三者評価と、処理時間・コストのトレードオフを示す。普段使いの候補はOpus 5、最高性能が必要ならFable 5、速度と料金を優先するならSonnet 5、という使い分けを、用途と費用の両面から説明する。

## 記事構成

### 結論：Opus 5は同じ価格で難しい仕事への対応力を高めた

冒頭で発表日、後継関係、価格据え置き、主な強化点を短く示す。記事が2026年7月26日時点の公式情報と第三者評価を整理したもので、筆者によるハンズオンではないことも明記する。

冒頭の直後に、Opus 4.8からOpus 5への進化を示すオリジナルのアイキャッチ兼記事内画像を配置する。

### Claude Opus 5とは

Opus 5は複雑なエージェント型コーディングと企業向け知識作業を想定したモデルであり、Claude Maxのデフォルトモデル、Claude Proで利用できる最上位モデルとして公開されたことを説明する。Claude API、Amazon Bedrock、Google Cloud、Microsoft Foundryでも利用でき、APIモデルIDは`claude-opus-5`である。

### Opus 4.8から強化された内容

変更点を「能力の強化」と「API・機能の変更」に分ける。

能力面では、公式ドキュメントが大きな改善として挙げる次の項目を、一般ユーザーにも分かる表現へ置き換えて説明する。

- 複数段階にまたがる深い推論
- 長時間のエージェント作業と複数ファイルにまたがる実装
- effortを上げたときに結果を改善する能力
- 低いeffortでも品質を保ちやすい効率
- コードレビューと不具合検出
- 画像、図表、画面デザインの理解
- 100万トークンの長い文脈での指示追従
- スプレッドシートやスライドなどの知識作業
- 複数エージェントの役割分担

API・機能面では、次の差分を比較表にする。

| 項目 | Opus 4.8 | Opus 5 | 移行時の意味 |
| --- | --- | --- | --- |
| APIモデルID | `claude-opus-4-8` | `claude-opus-5` | 呼び出し先を明示的に変更する |
| thinking | 明示しなければ無効 | デフォルトで有効 | 同じリクエストでも思考トークンを使う場合がある |
| effort | 利用可能 | `low`から`max`の5段階が結果へ強く影響 | まず`high`を基準に実測して調整する |
| thinkingの無効化 | effortと独立 | `high`以下でのみ可能 | `xhigh`・`max`と無効化の併用は400エラーになる |
| プロンプトキャッシュ最小長 | 1,024トークン | 512トークン | 短いプロンプトもキャッシュ対象にしやすい |
| 会話中のツール変更 | 固定が基本 | キャッシュを保った追加・削除がベータ提供 | 対応ベータヘッダーと仕様を確認する |
| Fast mode | 利用可能 | 約2.5倍速、基本料金の2倍 | 対応プラットフォームと費用を確認する |

thinkingがデフォルトになったことで、`max_tokens`が思考と最終回答を合わせた出力上限になる点を注意事項として扱う。API移行ではモデルIDだけを変更して終わらせず、既存のトークン上限、thinking、effort、テスト結果を確認する必要がある。

### 料金と基本仕様はOpus 4.8から据え置き

以下の基本仕様を簡潔な比較表にする。

| 項目 | Claude Opus 4.8 | Claude Opus 5 |
| --- | ---: | ---: |
| 入力料金 | $5 / 100万トークン | $5 / 100万トークン |
| 出力料金 | $25 / 100万トークン | $25 / 100万トークン |
| コンテキスト | 100万トークン | 100万トークン |
| 最大出力 | 128kトークン | 128kトークン |
| 相対的な速度 | 中程度 | 中程度 |

単価が同じでも、thinkingのデフォルト有効化とeffort設定によって実際の出力トークン、待ち時間、1タスク当たりの費用が変わる点を補足する。

### ベンチマークは公式評価と第三者評価を分けて読む

公式評価は、評価の目的を短く説明したうえで代表例に絞る。

- Frontier-Bench v0.1では、Opus 4.8の性能を2倍以上上回り、他モデルより高い結果とAnthropicが報告
- ARC-AGI 3では、次点モデルの3倍のスコアとAnthropicが報告
- OSWorld 2.0では、Fable 5の最高結果を約3分の1強の費用で上回ったとAnthropicが報告
- CursorBench 3.2のmax effortでは、Fable 5の最高値から0.5%以内、タスク費用は約半分とAnthropicが報告

数値や比較条件はAnthropicの発表に基づく「開発元による評価」であり、すべての実務を代表する結果ではないと明記する。

Artificial Analysisは第三者評価として別節または別表にする。2026年7月24日のAA-Briefcaseでは、Opus 5のmax effortが1720 Elo、Fable 5が1574 Eloで、Opus 5の1タスク当たり費用は$17.79、Fable 5は$22.30と報告されている。一方、max effortの平均処理時間は36.2分で、Opus 4.8の24.1分より長い。高いeffortは高性能だが、必ずしも速く終わる設定ではないという読み方を添える。

Artificial Analysisのグラフは転載せず、必要な数値を出典付きの独自表にまとめる。AA-Briefcaseが、複数ファイルからレポート、スライド、表計算などの成果物を作るエージェント型知識作業の評価であることも説明する。

### Fable 5・Sonnet 5との使い分け

公式ドキュメントのモデル比較を土台に、読者が判断しやすい3行の比較へ整理する。

| モデル | 標準API料金（入力 / 出力、100万トークン） | 向く用途 |
| --- | --- | --- |
| Claude Fable 5 | $10 / $50 | 費用より最高水準の能力を優先する、最も難しい長時間作業 |
| Claude Opus 5 | $5 / $25 | 複雑なコーディングや知識作業を日常的に任せる |
| Claude Sonnet 5 | $3 / $15 | 応答速度、処理量、費用のバランスを優先する |

Sonnet 5には2026年8月31日まで$2 / $10の導入価格があるため、記事の日付と標準価格を混同しないよう注記する。Fable 5は公式上の最も高性能な一般提供モデルだが、特定の評価ではOpus 5が上回るため、「常にFable 5が勝つ」「Opus 5がFable 5を完全に置き換えた」とは書かない。

### Claude Codeでは難しさと費用で選ぶ

一般的な修正、調査、繰り返し回数の多い作業ではSonnet 5、複数ファイルの大きな変更、難しい不具合調査、長時間の自律作業ではOpus 5、最も難しく費用を許容できる仕事ではFable 5、という選び方を提案する。

これは公式の能力・料金から筆者が整理する目安であり、実機比較の結論ではないと明記する。最終的には自分のコードベースと代表タスクで品質、所要時間、費用を測るよう促す。

### Opus 4.8からAPIを移行するときの確認事項

移行手順を次の短いチェックリストにする。

1. モデルIDを`claude-opus-5`へ変更する
2. thinkingがデフォルトで有効になる前提で`max_tokens`を見直す
3. `high`を基準にeffortを変え、品質・時間・費用を測る
4. thinkingを無効にする場合は`high`以下にする
5. ツール呼び出し、構造化出力、長時間タスクの回帰テストを行う
6. Bedrock、Google Cloud、Microsoft Foundryでは利用可能な機能差を確認する

会話中のツール変更や自動フォールバックはベータ機能なので、記事内の基本移行コードには組み込まず、存在と確認先だけを紹介する。

### まとめ

Opus 5は、料金と基本的なコンテキスト条件をOpus 4.8から据え置きながら、難しい推論、コーディング、長時間の作業を強化したモデルであるとまとめる。一方で、高いeffortほど処理時間とトークン消費が増える可能性があり、Fable 5・Sonnet 5との最適な選択は仕事の難しさと費用で変わる。API利用者はモデルIDだけでなくthinkingのデフォルト変更を確認する必要がある。
