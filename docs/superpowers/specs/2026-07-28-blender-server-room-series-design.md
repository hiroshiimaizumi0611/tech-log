# Blender 3Dサーバールーム連載 設計書

作成日: 2026-07-28
状態: ユーザー承認済み
対象: 第1連載（全4回）

## 1. 目的

Blenderを初めて触るインフラ／Webエンジニアに向けて、3Dサーバールームを作り、Webブラウザへ表示するまでの過程を全4回の記事にする。

この連載では、Blenderの網羅的な解説や精巧な3D作品の制作を目指さない。インフラエンジニアになじみのあるサーバーラックを題材に、必要な操作を使いながら覚える。最終的には、自作した3DサーバールームをGLBとして書き出し、React上で回転・ズームできる状態を完成とする。

主メッセージは次のとおり。

> Blender未経験のエンジニアでも、Cubeを中心にした小さな3Dモデルを作り、普段のWeb開発へ持ち込める。

## 2. 読者と執筆方針

### 2.1 想定読者

- Blenderを初めて触るインフラ／Webエンジニア
- ReactやTypeScriptには関心があるが、3D制作の経験はない人
- 一般的なBlender入門ではなく、技術者になじみのある題材で学びたい人

### 2.2 前提

- 執筆者のBlender経験はゼロから始める。
- 学習とスクリーンショット撮影にはmacOS版Blenderを使う。
- 記事ごとに、実際に使ったmacOSとBlenderのバージョンを記載する。
- Blenderの具体的な操作や仕様は、実機とBlender公式情報で確認した内容だけを書く。

### 2.3 記事の性格

記事は読者が同じ成果物を再現できる手順を主軸にする。学習日記だけにはせず、実際につまずいた点を補足として残す。

「初心者が迷った点」には、症状・原因・解決方法を確認できたものだけを載せる。原因が分からない現象は、推測で説明しない。

## 3. 第1連載の範囲

### 3.1 含めるもの

- Blenderのインストールと最初の画面操作
- 視点移動、オブジェクトの選択、移動、拡大縮小、複製
- Cubeを中心にしたサーバーラック、サーバー、床、壁の制作
- 最低限のマテリアル、照明、カメラ
- Web側で識別できるオブジェクト名
- Transformと出力対象の確認
- GLB形式での書き出し
- Vite、React、TypeScriptによる表示用アプリ
- React Three FiberとDreiによるGLB読み込み
- マウスによる回転とズーム

### 3.2 含めないもの

- 精巧なモデリング、テクスチャ制作、UV展開
- キャラクター、アニメーション、物理演算
- サーバーやラックのクリック選択
- 監視データ、詳細パネル、グラフ、状態別の色変更
- CloudWatch、API Gateway、LambdaなどのAWS連携
- WebSocketやリアルタイム更新
- モバイル向け3D操作の最適化
- 3Dアプリの本番公開

オブジェクト選択と監視データ連携は、第2連載の候補として扱う。第1連載へ追加しない。

## 4. 全4回の構成

連載全体の仮タイトルは「インフラエンジニアのためのBlender入門――3Dサーバールームをブラウザに表示する」とする。各記事のタイトルは、実際の成果やつまずいた点に合わせて公開前に微調整できる。

### 第1回: Blender完全初心者がCubeだけでサーバーラックを作る

扱う内容:

- Blenderのインストール
- 画面の見方
- 視点の回転、移動、ズーム
- オブジェクトの選択
- Cubeの移動と拡大縮小
- Cubeの複製
- ラックの枠とサーバーの配置

完成条件:

- Cubeを中心にしたサーバーラックが1台ある。
- ファイルを閉じて開き直しても、モデルが保存されている。
- 初心者が同じ手順を追って、近い形を再現できる。

### 第2回: ラックを並べて3Dサーバールームを作る

扱う内容:

- 床と壁の制作
- 第1回で作ったラックの複製と配置
- サーバーの追加
- 数種類に限定したマテリアル
- 1〜2個に限定したライト
- 完成状態を確認するためのカメラ

完成条件:

- ラック2台、床、壁があり、サーバールームとして判別できる。
- 色と照明によって、ラックと部屋の構造を見分けられる。
- 精巧さを追わず、第3回でGLBへ出力できる単純な構造を保っている。

第2回は他の回より作業量が多いため、2時間を少し超えることを許容する。

### 第3回: Blenderで作ったサーバールームをGLBに書き出す

扱う内容:

- オブジェクト命名
- 位置、回転、スケールの確認
- 出力対象と不要な要素の整理
- GLB形式での書き出し
- 別のGLBビューアーでの表示確認

命名の基本形:

```text
room_floor
room_wall_north
room_wall_south
rack_01
rack_02
server_01_01
server_01_02
server_02_01
server_02_02
```

完成条件:

- `server-room.glb`が生成されている。
- 別のビューアーで形、色、向きを確認できる。
- Web側で利用するオブジェクト名がGLB内に残っている。

### 第4回: React Three Fiberで3Dサーバールームを表示する

扱う内容:

- ViteによるReact＋TypeScriptプロジェクトの準備
- React Three FiberとDreiの導入
- Canvas、カメラ、ライトの設定
- `server-room.glb`の読み込み
- モデルの位置と大きさの調整
- OrbitControlsによる回転とズーム
- 読み込み中と読み込み失敗時の最低限の表示

完成条件:

- PCブラウザに3Dサーバールームが表示される。
- マウスで回転とズームができる。
- GLBがない、または読み込めない場合に、画面全体が無言で壊れない。
- Production buildが成功する。

## 5. 学習と執筆の進め方

各回は、1〜2時間の学習・制作を基本単位とする。作業を逐一文章化せず、次の順番で進める。

1. 作業前に、その回の完成条件と必要なスクリーンショットを決める。
2. ユーザーがBlenderまたはWebアプリを実際に操作する。
3. 操作中は、使った操作、迷った点、失敗だけを短く記録する。
4. 完成後、重要な操作をメモから再確認する。
5. 成功を再現できた内容だけで記事を書く。
6. 記事、画像、配布ファイルが同じ完成状態を示しているか照合する。

Codexは、各回の学習目標と手順の整理、疑問点の調査、メモの構造化、記事の下書きと推敲、検証項目の提示を担当する。Blenderの操作は原則としてユーザーが行い、操作そのものを自動化しない。これにより、実体験に基づいた記事を保つ。

## 6. 各記事の基本構造

各記事は次の順番を基本とする。内容が薄い節を無理に膨らませず、実際に重要だった部分を厚く書く。

1. 今回作るもの
2. 完成イメージ
3. 前回までの状態
4. 実際の操作手順
5. 初心者が迷った点
6. 完成確認
7. 今回覚えた操作
8. 次回予告

スクリーンショットは、読者が現在位置や選択対象を判断するために必要な場面へ絞る。同じ画面の細かな差分を大量に並べない。ショートカットを説明するときは、対応するメニュー名も可能な範囲で併記する。

## 7. リポジトリと成果物

ブログ本体と3D制作物は別リポジトリにする。

```text
tech-blog
├─ src/content/blog/               # 公開記事
└─ src/assets/blog/                # 軽量化した記事画像

3d-server-room-dashboard
├─ blender/
│  ├─ episode-01-rack.blend
│  └─ episode-02-server-room.blend
├─ public/models/
│  └─ server-room.glb
├─ src/                            # 第4回で追加
├─ docs/
│  └─ learning-log.md
└─ README.md
```

`3d-server-room-dashboard`は作業用の仮称とする。第1回の実装計画を開始する前に、作成場所とGitHub上の正式名称を確認する。

記事本文と軽量化済みの画像は`tech-blog`に置く。制作途中の`.blend`、GLB、Reactコード、加工前の事実メモは`3d-server-room-dashboard`に置く。記事と制作物の履歴を混ぜない。

各回の完成時点に、制作リポジトリで次のGitタグを付ける。

```text
episode-01
episode-02
episode-03
episode-04
```

これにより、読者は各記事と同じ状態の成果物を参照できる。`.blend`やGLBが通常のGit運用を妨げる大きさになった場合だけGit LFSを検討し、最初からは導入しない。

## 8. 確認と障害時の扱い

### 8.1 各回の確認

- `.blend`は保存後に閉じ、開き直して状態を確認する。
- 記事内の重要な操作は、執筆前にもう一度実行して確認する。
- 第3回では、Blender以外のGLBビューアーでモデルを開く。
- 第4回では、開発サーバー上の表示、回転、ズームを確認する。
- 第4回では、TypeScriptの検査とProduction buildを実行する。
- 公開前に、記事内のスクリーンショットと配布ファイルが同じ段階を示しているか確認する。

### 8.2 想定どおりに動かない場合

問題が起きたら、次を記録する。

- macOSとBlenderのバージョン
- 実行した操作
- 期待した結果
- 実際の結果
- 表示されたメッセージ
- 解決できた場合は原因と解決手順

調査中の推測は公開記事へ載せない。記事の手順そのものが再現できない場合は、その回を完成扱いにせず、原因の切り分けを優先する。
