# 第4回記事の3Dデモ導線改善 設計書

対象記事: 「React Three Fiberで3Dサーバールームを表示し、アラームで色を変える」

## 1. 目的

現在の記事には3Dデモへのテキストリンクが1つありますが、本文中の通常リンクに見えやすく、読者が操作できるデモの存在に気づきにくい状態です。

3Dデモへの導線を説明付きカードへ変更し、記事の冒頭側と末尾の2か所に配置します。読者が記事を読み始めたときと、読み終えたときのどちらでも、迷わずデモへ移動できることを目的とします。

## 2. 配置

同じ内容と見た目のカードを次の2か所へ置きます。

1. 「今回作るもの」でデモの機能と注意事項を説明した直後、最初のスクリーンショットより前
2. 「4回のまとめ」の最後

既存の単独テキストリンクは削除し、冒頭側のカードへ置き換えます。

## 3. カードの内容

カードには次の情報を表示します。

- 補助ラベル: `INTERACTIVE DEMO`
- 見出し: `3Dサーバールームを操作できます`
- 説明: 回転、ズーム、サーバー選択、アラーム発生と正常復帰を試せること
- リンク文言: `3Dサーバールームを開く`
- 補足: 別タブで開くことと、デスクトップ環境を推奨すること

表示する情報がモックデータであり、実際の監視サービスには接続していないことは、既存の本文で引き続き説明します。カード内では説明を重複させません。

カードはraw HTMLの`<aside data-demo-cta>`として記述し、内部の見出しには`<h3>`を使います。Markdown見出しではないため記事の目次抽出対象には含めず、同じ項目を目次へ2回追加しません。見出しに`id`は付けないため、2枚のカード間でIDが重複することもありません。

## 4. 見た目と操作

カードは既存ブログのデザイントークンを使い、記事本文になじむ見た目にします。

- 背景と境界線で通常の本文から区別する
- 補助ラベルと見出しで、操作できるデモであることを先に伝える
- リンクはアクセント色のボタンとして表示する
- カードは本文の先頭側へ寄せ、`inline-size: 100%`と`max-inline-size: 40rem`を指定する
- 40rem以下ではカードとボタンを利用可能な横幅いっぱいにし、ボタンの文字を中央へ置く
- 40remを超える画面では、ボタンを内容幅で表示する
- ホバー時だけでなく、キーボード操作時にも明確なフォーカス表示を出す
- 色だけに頼らず、文言と形でもリンクであることを示す

リンク先は既存の`/demos/server-room/`を維持し、`target="_blank"`と`rel="noopener"`も維持します。

## 5. 実装範囲

次のファイルを主な変更対象とします。

デモ本体、GLB、記事のメタデータ、canonical、サイトマップ、検索インデックス設定は変更しません。

## 6. 検証

自動テストでは次を確認します。

- 記事内にデモカードが2つある
- 両方のリンク先が`/demos/server-room/`である
- 両方に`target="_blank"`と`rel="noopener"`がある
- 両方のカードに補助ラベル、見出し、操作説明、別タブで開く案内、デスクトップ推奨の補足がある
- 冒頭側のカードが最初のスクリーンショットより前にある
- 末尾側のカードが「4回のまとめ」にある
- 公開デモから解説記事へ戻る既存導線が壊れていない

旧リンク文言と単一リンクを前提にしたテストは更新します。単体テストとE2Eでは`data-demo-cta`を使って2枚のカードを取得し、カード内のリンクをそれぞれ検証します。

記事のビルド、単体テスト、該当するブラウザテストを実行します。E2Eでは次も確認します。

- 1280px幅でカードが640pxを超えない
- 390px幅でカードとボタンが利用可能な横幅へ収まり、documentに横方向のオーバーフローがない
- Tabキーで各リンクへ移動でき、フォーカス時のoutlineが表示される
- 当該記事でaxeのcriticalまたはserious違反が0件である

## 7. 完了条件

- 記事を開いた読者が、3Dデモの存在と試せる操作をカードだけで理解できる
- 記事の冒頭側と末尾のどちらからでもデモを開ける
- 通常の本文リンクより明確に目立つ一方、既存ブログの落ち着いた外観を崩さない
- キーボードと画面幅の違いによってリンクが利用しにくくならない
