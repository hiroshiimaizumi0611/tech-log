ChatGPT Workは、調査や分析を進め、文書、表計算、プレゼンテーション、レポート、Siteなどの成果物を作るためのChatGPTの作業モードです。短いやり取りを中心とするChat、ソフトウェア開発を担当するCodexとは、目的で使い分けます。

> 提供プラン、対応画面、同期の説明は2026-07-11時点です。

本記事はOpenAIの[ChatGPT Work製品ページ](https://openai.com/chatgpt-work/)と[ChatGPT Work and Codexヘルプ](https://help.openai.com/en/articles/20001275-chatgpt-work-and-codex)を参照しています。段階的ロールアウト中のため、対象に見えるプランでもアカウントやワークスペースにまだ表示されない場合があります。

## Workとは

Workは、求める成果を伝えると、必要な文脈を集め、進め方を計画し、許可されたツールやファイルを使って成果物を作るための体験です。OpenAIは、長めの調査、情報分析、完成した資料の作成を主な役割として説明しています。

- 入力: ゴール、資料、制約、評価基準
- 作業: 文脈収集、質問、計画、許可された操作
- 出力: 文書、表計算、スライド、分析、レポート、Siteなど
- 利用者の役割: 計画、重要な操作、根拠、最終成果物を確認する

「ゴールだけで無条件にすべてを実行する機能」ではありません。利用できるファイル、アプリ、操作は、利用面、プラン、ワークスペース設定、ユーザー権限、接続先の権限に左右されます。

## Chatとの違い

Chatは、質問、検索、アイデア出し、短い会話型の支援に向きます。すぐに答えやたたき台が欲しい場合はChatが自然です。

一方Workは、複数の情報源を集め、途中の方針を確認し、共有できる形の成果物まで仕上げる仕事に向きます。単なる長文質問かどうかではなく、作業工程と成果物を管理したいかで分けます。

| 目的                                           | 選ぶ体験 |
| ---------------------------------------------- | -------- |
| 用語を確認する、短く相談する、アイデアを広げる | Chat     |
| 資料を横断してレポートやスライドを作る         | Work     |
| リポジトリを調べ、コードを変更し、テストする   | Codex    |

## Codexとの違い

Codexはソフトウェア開発と技術作業のための専用エージェントです。コードの作成・デバッグ、コマンドとテストの実行、変更レビュー、リポジトリ作業が中心です。

Workにも調査やファイル操作がありますが、役割の中心は業務資料や分析などの成果物です。たとえば、顧客調査から経営会議用レポートを作るならWork、アプリの不具合を再現して修正しテストするならCodexを選びます。レポートにコード断片が含まれるだけでCodexを選ぶ必要はなく、反対にREADMEを作るだけでもリポジトリ変更の一部ならCodexが適します。

## 使える環境

2026-07-11時点で、Workはデスクトップでは全プラン向けに提供され、Web・モバイルではPlus、Pro、Business、Enterprise、Eduへ数日かけてロールアウトすると[製品ページ](https://openai.com/chatgpt-work/)に記載されています。ヘルプでは、Web・モバイルは対象となる有料プラン、デスクトップはプランとワークスペースに含まれる場合に利用できると説明されています。実際のアカウント表示を優先してください。

| 環境                | Workの実行場所と扱い                                         |
| ------------------- | ------------------------------------------------------------ |
| Web・モバイル       | クラウドで動作。端末上のローカルファイルへ直接アクセスしない |
| ChatGPTデスクトップ | 許可したローカルファイルやデスクトップアプリを利用できる     |
| Codex               | デスクトップアプリのモード。Web・モバイルでは選択不可        |

公開時点では、クラウドで作成したWork会話は対応するクラウド面で継続できますが、デスクトップWorkには表示されません。デスクトップWorkのスレッドとローカルファイルはそのコンピューターに残ります。Chatの同期挙動をWorkやCodexへそのまま当てはめないことが重要です。

モバイルのRemoteタブから対応するデスクトップCodexタスクへアクセスできる場合がありますが、それはモバイルでCodexモードを選べることや、タスクがWeb・モバイルのチャット履歴になることを意味しません。

## ファイル・アプリ・成果物

Workは、指示と資料から文書、表計算、プレゼンテーション、レポート、分析を作成・編集できます。[成果物作成の公式ガイド](https://help.openai.com/en/articles/20001278-creating-and-editing-documents-spreadsheets-and-presentations-with-chatgpt-work)では、出力形式、変更してはいけない要素、参照テンプレートを明示し、共有前にレビューする手順が推奨されています。

デスクトップでは、必要なローカルフォルダやファイルだけにアクセスを許可します。Web・モバイルのWorkはコンピューター上のファイルを直接読めないため、クラウド側で使える資料を追加する必要があります。

接続アプリについても、すべてが自動的に使えるわけではありません。

- 対応するアプリが有効化・接続されていること
- ワークスペース管理者が許可していること
- ユーザーが接続先のファイルや操作権限を持つこと
- 対象のファイル形式と利用面が対応していること

たとえば、対応環境ではGoogle Docs、Sheets、Slidesを扱えますが、関連するGoogle Workspaceアプリの有効化と接続が必要です。デスクトップのMicrosoft Excel対応にも専用アドインが関係し、PowerPointは公開時点の同じデスクトップフローには含まれないと公式ガイドは説明しています。

## Planと承認

Planモードでは、Workが文脈を集め、必要な質問をし、段階的な計画を提示します。利用者は内容を修正するか、承認して作業を開始できます。

計画レビューでは、少なくとも次を確認します。

1. 使う資料と対象期間が正しいか
2. 不足情報を推測せず、未確認として扱うか
3. 出力形式、読者、分量、締切が明確か
4. 外部への作成・更新・送信が含まれるか
5. 最終確認を誰が行うか

計画の承認は、以後のすべての操作を包括的に許可することとは限りません。重要な操作では確認を求められる場合があり、承認の出方はアプリ権限や操作内容によって異なります。進捗を見て質問へ答え、方向を変え、重要な操作と成果物を確認する前提で使います。

## 具体的な利用例

ここでは、複数文書から月次レポートを作る例を示します。

1. **ゴール入力**: 「6月の顧客動向を役員向けに5ページでまとめる。数値は添付資料のみを根拠にし、事実・解釈・提案を分ける。未確認事項は明記する」と伝える
2. **文脈収集**: 対象の売上表、顧客インタビュー、前月レポート、書式テンプレートを追加する。Workには対象期間と優先資料を確認させる
3. **計画レビュー**: 資料一覧、指標の定義、章立て、出典の付け方、矛盾時の扱いを確認し、必要なら修正してから承認する
4. **成果物レビュー**: 数値を原資料と照合し、引用元、計算、グラフの軸、事実と提案の区別を人が確認する。修正後に共有する

この流れでは、資料を渡すことよりも「使ってよい根拠」「判断基準」「未確認情報の扱い」を先に定義することが重要です。Workが作った見栄えのよい成果物も、内容の正しさを自動的に保証しません。

## 向く仕事・向かない仕事

Workに向くのは、次のような仕事です。

- 複数資料から出典付きのレポートを作る
- 既存テンプレートに沿って表計算やプレゼンテーションを更新する
- 調査、分析、構成、成果物レビューをひとつの作業として進める
- 計画を確認しながら、長めの仕事を段階的に進める

一方、次の場合は別の方法か、人の判断を中心にします。

- 一問一答や短い相談だけならChatの方が簡潔
- リポジトリ、端末、テストを中心に扱う開発作業ならCodexが担当
- 利用権限のないデータや、未接続のアプリを前提にする仕事
- 医療・法務・金融・人事など、専門家による最終判断を省けない仕事
- 根拠資料がなく、正確性を検証できない成果物

最初は、資料範囲が明確で、結果を人が照合できる低リスクな成果物から始めます。利用できる面と権限を確認し、Planで工程を合わせ、共有前に原資料と成果物をレビューするのが安全な使い分けです。
