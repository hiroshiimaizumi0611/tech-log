GPT-5.6は、ひとつのモデル名ではなく、Sol・Terra・Lunaという3つの能力階層を持つモデルファミリーです。選ぶときは「常に最上位」ではなく、必要な品質、待ち時間、APIコスト、利用する製品を分けて考える必要があります。

> 料金、対象プラン、ロールアウト状況は2026-07-11時点の情報です。

この記事の事実関係は、OpenAIの[GPT-5.6発表](https://openai.com/index/gpt-5-6/)と[ChatGPTでの提供条件](https://help.openai.com/en/articles/20001354-gpt-56-in-chatgpt)に基づきます。以下の「向いている」は、公式の位置付けを踏まえた本記事の選択指針です。

## 3モデルの位置付け

OpenAIは、モデル名の数字を世代、Sol・Terra・Lunaを独立したペースで更新できる能力階層と説明しています。

| モデル        | 公式の位置付け               | 選択時の軸                             |
| ------------- | ---------------------------- | -------------------------------------- |
| GPT-5.6 Sol   | フラッグシップ               | 難しい推論や専門的な成果物の品質を優先 |
| GPT-5.6 Terra | 能力・速度・コストのバランス | 日常的な業務を広く処理                 |
| GPT-5.6 Luna  | 最速かつ最も低コスト         | 大量処理や短い応答を優先               |

この表の「選択時の軸」は推薦であり、個々のタスクで必ず優劣が固定されるという意味ではありません。重要な業務では、自分の入力と評価基準を使って小さく比較してから決めます。

## Sol

SolはGPT-5.6のフラッグシップです。OpenAIは、コーディング、知識労働、サイバーセキュリティ、科学、コンピューター操作、デザインを含む複雑な仕事向けと説明しています。通常のChatGPTでMedium以上の推論を選んだときに使われるGPT-5.6もSolです。

本記事では、次の条件に当てはまるときSolを第一候補にします。

- 複数の資料を統合し、根拠と結論の整合性を確認する
- コード、文書、表、スライドなど、修正コストの高い成果物を作る
- 速度や単価より、難しい制約を満たす確率を優先する

標準ChatGPTには、難しい仕事や長時間のワークフロー向けの「GPT-5.6 Sol Pro」もあります。これはSol・Terra・Lunaという3階層の料金比較とは別のChatGPT上の選択肢です。

## Terra

Terraは、日常業務における能力、速度、コストのバランスを取る階層です。最上位品質を毎回要求しない一方、単純な分類だけではなく、要約、調査整理、一般的な実装や分析まで扱いたい場合の出発点になります。

推奨の使い方は、まずTerraで評価セットを処理し、品質基準を満たさない難問だけSolへ振り分ける方法です。ただし、自動振り分けの仕組みはGPT-5.6の提供仕様ではなく、利用者側で設計する運用です。

## Luna

LunaはGPT-5.6ファミリーで最速、かつAPI単価が最も低い階層です。入力形式と期待する出力が明確で、一件あたりのコストや待ち時間を抑えて件数を処理したい場合に向きます。

- 定型文の下書き
- 明確なラベルへの分類
- 短い要約や項目抽出

「速いから常に最適」とは限りません。誤りの確認や再実行が増えると総コストが上がるため、正解例と失敗例を含む評価データで確認します。

## ChatGPT・Work・Codex・APIでの提供差

2026-07-11時点では、製品ごとに選べるモデルが異なります。ロールアウト中のため、対象プランでもアカウントにまだ表示されない場合があります。

| 利用面       | GPT-5.6の提供状況                                                                                         |
| ------------ | --------------------------------------------------------------------------------------------------------- |
| 標準Chat     | PlusはSolのMedium・High。Pro、Business、EnterpriseはSolのMedium・High・Extra High・Pro。Free・GoはSolなし |
| ChatGPT Work | Plus、Pro、Business、EnterpriseでSol・Terra・Luna。発表上、Free・GoはTerra                                |
| Codex        | Free・GoはTerra。Plus、Pro、Business、EnterpriseはSol・Terra・Luna                                        |
| OpenAI API   | Sol・Terra・Luna                                                                                          |

特に、**TerraとLunaは標準ChatGPTの会話では選択できません**。標準ChatではGPT-5.5 Instantが日常応答の既定で、GPT-5.6 Solは対象プランの推論設定から使います。Work・Codex・APIとの違いは[GPT-5.6 in ChatGPTの提供表](https://help.openai.com/en/articles/20001354-gpt-56-in-chatgpt)で明記されています。

また、WorkやCodexを利用できることと、すべてのモデル・推論設定を選べることは同義ではありません。プラン、管理ワークスペースの設定、アプリのバージョン、段階的ロールアウトを確認します。

## 用途別選択

選択は次の順で行うと整理しやすくなります。

1. 標準Chat、Work、Codex、APIのどこで処理するか決める
2. 許容できる誤り、待ち時間、1件あたりの予算を数値化する
3. Terraを基準に、品質不足ならSol、速度・費用を下げたいならLunaを比較する
4. 実データの代表例と難例で、品質、所要時間、総トークンを記録する

機密情報、外部アプリへの操作、コード実行が関係する場合は、モデル比較だけでなく製品側の権限と承認設定も評価対象です。

## 具体的な選択例

### 速度優先

入力条件は「200文字以内の問い合わせを、既定の8分類のいずれかへ分類し、理由を1文で返す」、許容時間は短く、人が低信頼結果を確認できるとします。

1. Lunaで代表例と境界例を処理する
2. 分類精度と再確認率を測る
3. 基準を満たさない場合だけTerraを比較する

理由は、Lunaが公式に最速の階層とされ、形式が限定された短い処理では上位モデルの追加能力が不要な可能性があるためです。

### コスト優先

入力条件は「毎日5万件の商品説明から3項目をJSONで抽出」、出力検証をスキーマで自動化でき、月間予算が固定されているとします。

1. Lunaの入力・出力トークンを実測する
2. 失敗時の再試行まで含めて1万件あたりの費用を算出する
3. 誤抽出の修正費を含む総コストが高ければTerraへ上げる

単価だけならLunaですが、推薦の根拠は「請求単価」ではなく「検証と再処理を含む総費用」です。

### 複雑な専門業務

入力条件は「契約書、社内規程、会議記録を横断し、主張ごとに参照元を付けた意思決定メモを作る」、不明点は推測せず明示し、公開前に専門家が確認するとします。

1. Solへ成果物の構成、引用ルール、判断してはいけない事項を渡す
2. 根拠のない主張と資料間の矛盾を確認する
3. 専門家が原文と照合して承認する

複数資料の統合と難しい制約への追従を優先するため、Solを第一候補にします。Solを使っても専門家の判断を代替するわけではありません。

## 注意点

- 発表時のベンチマークは、自社タスクの品質を保証しません
- プランの対象でも、段階的ロールアウトや管理者設定で表示が異なる場合があります
- API料金とChatGPTのプラン料金を混同しないでください
- 推論レベル、ツール、コンテキスト、出力長が違えば、同じモデル名でも所要時間と費用は変わります
- 医療、法務、金融、セキュリティなど高リスクの判断では、原資料との照合と適切な専門家のレビューが必要です

まず小さな評価セットで比較し、品質・時間・総費用を同じ条件で記録することが、モデル名だけで選ぶより再現性のある方法です。
